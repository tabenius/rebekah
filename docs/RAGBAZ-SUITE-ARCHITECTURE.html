End-to-end operating flow

Boot and recover. v-BAZ starts the Alpine A/B host, mounts durable storage, and loads either online images or verified offline artifacts.

Compose safely. Rebekah starts isolated OpenCode, Ollama, Sylvae and WeftMark services; only its authenticated gateway is intended to face a user or LAN.

Claim work. WeftMark binds a task and Change Set to exact Git lineage, scopes and a time-bounded claim.

Execute. Sylvae runs a portable SKILL.md against Ollama, OpenCode, Codex, Claude Code or an API backend and appends a durable run record.

Correlate. A preallocated UUID yields sylvae:run/<id>. WeftMark records that opaque producer identity on commit-bound evidence.

Review in context. Rebekah resolves the producer identity and exposes Change Set → Sylvae/OpenCode links without guessing or becoming a second source of truth.

V

v-BAZ

github.com/tabenius/v-BAZ · default branch: main
USB Phase 2 active

Portable machine substrate and installer: firmware, disks, boot, durable storage, isolated runtimes and offline artifact delivery.

Owns

  • UEFI boot and Alpine A/B root slots
  • Host storage and persistence
  • VM/container runtime provisioning
  • Rebekah lifecycle on the host
  • Offline image/model staging

Does not own

  • Agent work readiness
  • Skill semantics or model routing policy
  • Rebekah’s user/session API
  • Evidence review decisions
Portable USB Phase 2

Kali persistence storage and checksum-pinned ISO staging are implemented and CI-proven. Remaining gates are Kali host autostart/boot wiring, reproducible first-boot customization and persistence across two complete outer-host reboots.

R

Rebekah

github.com/tabenius/rebekah · default branch: main
integration branch active

The suite composition and experience layer: one image, one authenticated front door and a human interface that keeps underlying authorities intact.

Owns

  • Nix-pinned component composition
  • Service supervision and isolation
  • Gateway authentication and proxy policy
  • Human-facing console and aggregate APIs
  • Optional Ephor connector boundary

Design invariant

Rebekah correlates and explains. It does not reimplement WeftMark’s readiness rules, Sylvae’s execution record, Ollama’s model store or OpenCode’s agent session engine.

Runtime link slice

The gateway consumes WeftMark evidence_refs, recognizes explicit sylvae:run/… and opencode:session/… producers, and otherwise displays “not linked yet.” No join is fabricated from branch names.

W

WeftMark

github.com/tabenius/WeftMark · default branch: main
runtime identity slice

Evidence-bearing control plane around software workers. Git supplies lineage; WeftMark supplies claims, causal evidence, review and handoff.

Core model

  • Tasks and Change Sets
  • File and semantic scopes
  • Claims and Git observations
  • Typed evidence and artifacts
  • Review, readiness and handoff

Runtime neutrality

Producer IDs remain opaque. WeftMark stores sylvae:run/… or opencode:session/… but does not classify vendors. Consumers decide how to resolve them.

Evidence runtime identity

The detail route surfaces evidence producer and artifact references while the board remains lean. CLI evidence capture accepts explicit producer kind and ID. Work in this repository remains subject to dual Frog + native WeftMark claim protocol.

S

Sylvae

github.com/tabenius/sylvae · default branch: master
CLI + MCP identity

Portable skill execution across local models, APIs and agent harnesses, with append-only run evidence and explicit resource consequences.

Owns

  • SKILL.md loading and validation
  • Backend selection and execution
  • Timeout, recursion and cost guards
  • Append-only run evidence
  • Stable cross-system run identity

Backends

  • Ollama: local/offline default
  • OpenCode and Codex: agent harnesses
  • Claude Code: explicit interactive quota
  • Anthropic API: separately credentialed
Cross-system identity

Every run has a stable sylvae:run/<uuid> reference. CLI and MCP callers may preallocate the canonical UUID so the real Sylvae command and WeftMark evidence share one identity. MCP results return both run_id and runtime_ref.
